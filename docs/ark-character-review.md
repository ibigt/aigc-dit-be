# 角色审核与方舟拉取图片

本文给接手「方舟能下载到角色图」的同事。审核主流程已经在业务里。公网图片地址这一段按**还没做**来设计和实现；仓库里如果出现 `S3_PUBLIC_ENDPOINT`、`dit.s3.public-endpoint` 一类草稿，不要沿用。

## 1. 要解决的问题

Seedance 出视频时，角色参考图需要先进入火山方舟素材库，变成 `asset://{AssetId}`。方舟创建素材时不会收我们服务器上的文件，它只收一个 **URL**，然后由**火山机房自己**去下载这张图。

现在对象存储是 Docker 里的 MinIO，地址类似 `http://minio:9000`。点「角色审核」时，后端签出的临时链接也是这个内网 HTTP 地址。业务代码发现链接不是 `https://` 开头，就直接失败，提示：

> 当前存储签不出公网图片地址，不能入库

这一步还没有调用方舟。接手人要做的是：让审核提交给方舟的 URL，从火山机房用 HTTPS 能在有效期内下载到图片字节。

## 2. 审核方案（已有行为，不要改产品语义）

只审核**当前选中的那张角色图**。场景、道具、分镜镜头没有这个按钮，也不会自动入库。

用户在角色资产的生成记录标题栏点击「角色审核」（在「切换最终资产」左侧）：

| 状态 | 按钮 | 含义 |
| --- | --- | --- |
| 已选图，尚未入库 | 蓝色「角色审核」 | 可以点 |
| 请求进行中 | 灰色「审核中」 | 不可再点 |
| 该图已是 Active | 灰色「已审核」 | 短路由，不再请求方舟 |
| 没选图，或页面正忙 | 灰色「角色审核」 | 不可点 |

切换到另一张已经 Active 的图，按钮显示「已审核」。切换到没审核过的图，按钮回到「角色审核」。不要在切换图片时删掉其他图已经 Active 的素材。

入库规则：

- 整个环境只建一个素材组。名称 `aigc-dit`，描述 `aigc-dit 虚拟人像`，类型 `AIGC`。返回的 `group-...` 记下来重复使用。
- 素材名称是 `drama-{seriesId}-{assetId}`，最长 64 字符。这个名字只给检索，不写进视频提示词。
- 同一张图如果上次是 Failed，先删掉旧素材再创建。状态还是 Processing 时，接着轮询原来的素材 ID，不要再创建一条。
- 创建后每 3 秒查询一次，最多约 120 秒。超时提示「角色审核超时，请再点一次」，记录保持 Processing，下次点击接着查。
- 只有状态变成 Active，后续出片才使用 `asset://{AssetId}`。
- 失败时把方舟原文返回给用户，例如 `InputImageSensitiveContentDetected: 人脸不一致`。不要改写成别的文案。
- 删掉某条生成记录，或删掉整个角色时，释放对应的远程素材。
- 出片选图顺序：Active 的 `asset://`，其次未过期的 Seedream 5.0 原链，最后 Base64。`asset://` 放进现有的 `image_url.url`。不要把 GetAsset 返回的临时 URL 拿去出片。
- 出片阶段若方舟把参考图判成真人脸，沿用现有停片提示，并且不要改用原链或 Base64 再送一次。

真人照片即使用公网 URL 送进去，方舟仍可能以真人脸拒绝。那是素材内容问题，不是下载地址问题。虚拟人像应使用 Seedream 5.0 生成。

## 3. 方舟接口（审核调用，已接通）

素材库是控制面，**只接受 Access Key / Secret Key 的 HMAC-SHA256**。Seedance 模型上的 Bearer API Key 只能打数据面 `https://ark.cn-beijing.volces.com/api/v3`，不能用来创建素材。不要做「用某个模型的 API Key 审核」的开关。

控制面：

```text
POST https://ark.cn-beijing.volcengineapi.com/?Action=CreateAssetGroup|CreateAsset|GetAsset|DeleteAsset&Version=2024-01-01
```

签名是火山 V4：密钥原文参与 HMAC，不加重置前缀。签名头为 `content-type`、`host`、`x-content-sha256`、`x-date`。凭证范围是 `YYYYMMDD/cn-beijing/ark/request`。

创建素材的 JSON 字段顺序保持为：`GroupId`、`URL`、`Name`、`AssetType=Image`、`ProjectName`。

密钥在管理端「模型管理 → 配置审核密钥」里填写，AES-GCM 加密后存入 `ark_review_credential`（全环境一行）。接口只返回是否已配置，不回传明文。库里有值时优先用库里的；没有时才回退到环境变量 `ARK_ACCESS_KEY`、`ARK_SECRET_KEY`。两项都空时，审核提示「请先在模型管理中配置审核密钥」。

项目名默认 `default`。账号若返回项目名无效，再改 `ARK_PROJECT_NAME`。素材组 ID 留空，由程序创建并记住。

## 4. 待开发：方舟下载图片的地址

集成点在角色审核里，创建素材之前：

```text
url = objectStorage.presignGet(当前角色图的 storageKey, 20 分钟)
```

随后检查：去掉空白后，必须以 `https://` 开头，否则抛出「当前存储签不出公网图片地址，不能入库」，并且**不要**创建素材组、不要调用 CreateAsset。

接手人要保证这个 `url` 满足下面全部条件。

1. 火山机房（公网）能在 20 分钟内 GET 到图片正文，HTTP 状态 200，正文就是这张图。
2. 协议是 HTTPS。证书由公网信任的 CA 签发。自签名、内网 CA、过期证书都会在方舟侧失败。
3. 方舟实际请求的主机名、路径、查询参数，必须和签名时一致。反向代理要保留原始 `Host` 和 query，不能把 Host 改成 `minio:9000`。
4. 业务服务器读写对象存储可以继续走内网，例如 `http://minio:9000`。交给方舟的地址单独是公网地址。不要把业务读写也改成只走公网，否则容器内上传下载会断。
5. 桶保持私有即可。临时签名本身能授权这一次下载，不必把整个桶设成公共读。
6. 有效期按现有 20 分钟。审核轮询最长约 120 秒，链接在这次审核结束前必须仍有效。

当前部署里 MinIO 默认是：

```text
S3_ENDPOINT=http://minio:9000
桶名 dit
路径风格：https://主机/桶名/对象键?X-Amz-...
```

`http://公网IP:9000` 不能满足第 2 条。只开放 9000 端口也不能代替 HTTPS。

### 4.1 多台业务服务器

可以只准备**一台**公网机器作为下载入口，几台业务服务器共用它。方舟只访问这一台。

可行做法：各业务服务器把对象写到这台公网 MinIO（内网或专线可达），用**不同桶名**区分环境。签名路径里的桶名已经能区分来源，例如：

```text
https://files.example.com/dit-服务器甲/对象键?...
https://files.example.com/dit-服务器乙/对象键?...
```

不可行做法：在已经签好的路径前面再加一段自定义后缀，例如把 `/dit/a.png` 改成 `/server-a/dit/a.png`。签名覆盖了路径，方舟或 MinIO 按改过的路径校验会失败。若必须用路径前缀区分，前缀得在签名之前就进入规范路径，并且 MinIO 收到的路径和签名路径相同。这比分桶更容易签错，不建议作为第一版。

各业务机自己的 MinIO 如果公网入口访问不到，就不能只做域名转发。入口机器必须能读到字节：要么业务机直接把文件写到这台 MinIO，要么入口再向业务机拉取。后者要另外做短时票据和转发，当前代码没有这一层。

### 4.2 域名是不是必须

多台机器共用一个入口时，用域名。一台公网机器绑定域名，Caddy 或 Nginx 把 `443` 反代到本机 MinIO 的 `9000`，申请 Let’s Encrypt 证书。各业务机配置的「交给方舟的地址」都是 `https://这个域名`，再用桶名区分。

域名购买和 DNS 解析可以自己完成。服务器在中国大陆、并且用域名对外开放 80/443 时，云厂商通常要求先做 ICP 备案，备案通过前 443 往往从公网打不开。机器在香港或海外则没有这一步。

不用域名也可以做 HTTPS，但只适合**一个公网 IP、一套入口**。Let’s Encrypt 从 2026 年 1 月起可以给公网 IP 签发证书，有效期大约 6 天，必须自动续期。地址形如 `https://公网IP/桶名/对象键`。证书签的是 IP，不包含端口；一个 IP 不能再拆成多个主机名。Caddy 按域名申请证书很直接，按 IP 申请要单独走 Certbot 的 `shortlived` 配置。

因此：

- 只要有多套部署，用一个域名加不同桶名。
- 纯 IP 的 HTTPS 能满足「必须是 https」这一条，但证书 6 天就过期，也不适合再按主机名拆多套环境。
- `http://IP:端口` 不能满足要求。

## 5. 验收

1. 在火山机房能够到达的网络里（至少是一台公网机器，不要在业务机内网里自测）执行 `curl -I "交给方舟的那条 https 链接"`，结果为 200，且证书校验通过。
2. 管理端已配置审核密钥。选中一张 Seedream 5.0 生成的虚拟角色图，点击「角色审核」。
3. 不再出现「当前存储签不出公网图片地址，不能入库」。
4. 成功时按钮变为「已审核」。之后用该角色出 Seedance 视频时，参考图使用 `asset://`。
5. 真人照片允许失败，失败文案应是方舟原文，而不是下载地址那句提示。

## 6. 建议不要做的事

- 不要用模型 API Key 代替 Access Key / Secret Key。
- 不要为了过审核把桶改成永久公共读，除非另有明确的安全评审。
- 不要在审核失败后自动改用 Base64 或内网地址再提交一次。
- 不要把 GetAsset 返回的临时 URL 写入出片请求。
